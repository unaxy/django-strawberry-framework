## Confirmed defect and repair

### Read-only defaults can activate an unguarded uniqueness query

**ID:** `FIX100-02-READONLY-DEFAULT-UNIQUENESS` — attributed to `13982ba895f2f32a7fc9114ae17b1c9a0c40f031`; reviewer severity P1; fixed.

**Contract:** the [serializer spec][serializer-spec] row “A bind check at every level” requires an unbindable nested uniqueness value to return the field’s `invalid` error with nothing written.

A supported nested serializer can declare a writable temporal or duration field and a read-only default partner in a `UniqueTogetherValidator`. The package checked attrs before DRF supplied that partner, predicted no query would run, then let DRF add the default and bind the unrepresentable value. On SQLite this can escape as an `OverflowError` and become a masked top-level GraphQL error.

The [production repair][serializer-resolvers] installs a leading context-aware validator in the serializer instance’s validator list. DRF’s own `Serializer.run_validators` supplies defaults once, then invokes the guard with the exact mapping later validators receive. The guard aggregates refusals before uniqueness queries, includes read-only bound fields, and preserves the original validators and their order. The adversarial reviewer accepted the completed implementation after tracing the default merge and dictionary-shaped validation-error behavior.

Added regression coverage:

- [Live GraphQL cases][live-regressions] exercise the nested read-only default with an unbindable datetime and an in-range control through the scalars example mutation.
- [Package regression][package-regressions] exercises the nested duration counterpart and asserts a callable read-only default runs once.
- The [example serializers][example-serializers], [example mutation][example-schema], serializer spec, and [live suite map][live-map] describe the concrete supported shape.
